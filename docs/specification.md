# 🎾 ダブルスマッチングシステム 仕様書 Ver1.2

## 概要

テニス部のダブルス練習会向けの試合運営アプリ。

管理者が参加者・コート・試合結果を管理する。試合終了後にコートを空き状態に戻し、管理者がその空きコートから自動マッチングまたは手動入力を逐次実行する。

参加者はリアルタイムで以下の情報を確認できる。

- 現在の試合状況
- コート状況
- ランキング
- MVP / SVP
- 試合履歴

# プレイヤー管理

## レベル

- 上級 = 3（評価値300）
- 中級 = 2（評価値200）
- 初級 = 1（評価値100）

## ステータス

- 待機中（青）
- 試合中（赤）
- 休憩中（グレー）

休憩中・試合中はマッチング対象外。

---

# コート設定

- 1〜6面
- 選出人数 = コート数 × 4人

例：3面 → 12人選出

---

# 試合形式

- 4ゲーム固定
- 勝ち +3pt
- 引き分け +1pt
- 負け -1pt

入力例：

```text
4-0
3-1
2-2
```

# マッチングと試合進行（Ver1.2）

## 方針
- NEXT MATCH（次試合の事前生成・予約・表示）は行わない。
- 管理者が現在の試合結果を登録すると、該当コートは即座に「空き」に変わる。
- 次試合を始める際は管理者が空きコートのカードをタップし、「自動マッチング」か「手動入力」を選ぶ。
- 自動マッチングは**選択した1コートに対してのみ**実行する。管理者の操作がない間に次試合は生成しない。
- 参加者はコート・試合・戦績を閲覧できるが、マッチングやスコア登録はできない。
- 休憩中・試合中の選手は候補から除外。選手の怪我・途中退出などは休憩（参加不可）に変更して対応。
- 候補選出後も試合開始直前に4名の選出可能状態・重複・コートの空きを再検証する。

## 自動マッチングの選出ルール
1. 待機中の選手から選出する。
2. 試合数の少ない選手を優先する。
3. 選手の評価値 = level × 100 + point × 10 とする。
4. 直近の同じペアを避ける（ペア履歴は `p1` と `p2` の一貫した形式で参照）。
5. 4名のチーム分けは戦力差が小さくなる組み合わせを優先する。
6. 生成した組み合わせを管理者が確認し、開始を押して初めて試合中へ変更する。

## 手動入力
- 管理者が待機中の選手4名を指定し、チームA・Bに2名ずつ割り当てる。
- 選手重複・待機以外の選手の選択を禁止する。
- 開始確定前に組み合わせを確認できる。

## 結果登録
- 管理者が試合中のコートを選択し、4ゲーム制のスコアを登録する。
- 合計ゲーム数が4であることを入力時に確認する。
- 登録後は戦績・ポイント・試合履歴を再計算し、該当コートを「空き」にする。
- 次試合は生成されず、管理者が次の空きコート操作を行うまで空きのまま。

## コートカードの画面デザイン
- PC・スマホともテニスコートを俯瞰した背景とネット・ラインを表示する。
- 試合中：コート上側にチームA、ネット中央にVS、下側にチームBを等しい文字サイズで重ねる。
- コート下部に「タップして結果を入力」の導線を置く（管理者）。
- 空き：選手名を表示せず、管理者には「タップしてマッチングを選択」を表示する。
- 参加者には情報の閲覧のみを許す。

## ランキング
- 画面読み込み時に常に表示する。
- 「ランキングを更新」で最新状態を再描画する。非表示切り替えは設けない。
- ポイント降順、選手名を大きく表示し、ポイントの下に勝利／敗北／引き分けの順で `3/1/1` と表示する。

## データ・権限
- Firestore同期や既存の履歴・得点処理を維持する。
- フロントエンドの管理者パスワードチェックは暫定的なUI制御であり、強固な認証ではない。公開時にはFirebase AuthenticationとFirestoreルールにより管理操作を保護する。
- 複数端末間での同時操作に対しては、試合開始・結果登録をサーバー側またはトランザクションで排他制御する必要がある。
