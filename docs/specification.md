# 🎾 ダブルスマッチングシステム 仕様書 Ver1.1

## 概要

テニス部のダブルス練習会向けの試合運営アプリ。

管理者が参加者・コート・試合結果を管理する。次の試合はシステムが自動マッチングで継続的に提案し、管理者は必要な場合だけ手動修正する。

参加者はリアルタイムで以下の情報を確認できる。

- 現在の試合状況
- 自動提示された次の試合（NEXT MATCH）
- コート状況
- ランキング
- MVP / SVP
- 試合履歴

# プレイヤー管理

## レベル

- 上級 = 3（評価値300）
- 中級 = 2（評価値200）
- 初級 = 1（評価値100）

## ステータス

- 待機中（青）
- 試合中（赤）
- 休憩中（グレー）

休憩中・試合中はマッチング対象外。

---

# コート設定

- 1〜6面
- 選出人数 = コート数 × 4人

例：3面 → 12人選出

---

# 試合形式

- 4ゲーム固定
- 勝ち +3pt
- 引き分け +1pt
- 負け -1pt

入力例：

```text
4-0
3-1
2-2
```

# 自動マッチングと次試合の継続提示（Ver1.1）

## 基本方針

- 次試合はシステムが自動生成・提示する。通常運用では管理者による「自動マッチング実行」操作は不要。
- コート状況に各コートの「現在の試合」と「NEXT MATCH（次の試合）」を表示する。
- 自動提示されたNEXT MATCHは管理者・参加者の双方にリアルタイム表示する。管理者のみ手動修正・取消・試合開始が可能。
- 手動修正は**自動提示後**に行う。管理者が選手4名とチームの組み合わせを修正して再提示できる。
- **一度提示した次試合は原則固定**。別の試合の結果更新などで黙って入れ替えない。手動修正済みの組み合わせも自動計算で上書きしない。
- 既存の自動マッチングアルゴリズムの優先順位・評価式を継承する。

## 自動マッチングの既存アルゴリズム

1. 試合数が少ない選手を優先
2. 待機中の選手のみ対象
3. レベルとポイントによる戦力評価
4. 直近10試合の同一ペア回避
5. チーム間の戦力差を最小化

評価値：

```text
(level × 100) + (point × 10)
```

ペア履歴は選手ID同士の一貫した形式で記録・判定すること。実装時に既存コードの形式不整合を解消する。

## 次試合の自動生成契機

- 大会開始時または参加者が4名以上揃い、未提示の対象コートがあるとき
- 試合結果登録でコートが空いたとき
- 選手の追加・待機／休憩変更、コート数変更、次試合の取消などで選出条件が変わったとき
- 既存のNEXT MATCHは保持し、**空いている次試合枠のみ**自動補充する
- 競合する更新が連続した場合も同一条件の再処理で重複試合が作成されないこと（冪等性）

生成処理は共有データの確定状態を基準に一度だけ行う。各閲覧端末が個別にマッチングしてFirestoreへ書き込む方式にはしない。認証済みの管理処理または信頼できるサーバー側処理で排他・整合性を担保する。

## コートごとのNEXT MATCH

- コート数は既存どおり1〜6面。各コートが保持できるNEXT MATCHは最大1件。
- 試合中のコートにも次試合を事前提示できる。現在の試合終了後に開始可能になる。
- 選出対象は待機中で、現在の試合にも別コートのNEXT MATCHにも割り当てられていない選手のみ。
- NEXT MATCHに選出した選手は**予約済み**として他の次試合の候補から除外する。ただし試合開始まではプレイヤーの「試合中」状態には変更しない。
- 4名に満たない、または候補者不足の場合は「マッチング待ち」を表示し、条件を満たした際に再試行する。
- NEXT MATCHが提案済みでも、対象コートが試合中なら開始ボタンは無効。
- コートが空き、かつ選手4名が有効・参加可能な場合にのみ管理者が「試合開始」できる。開始と同時に予約を解消し、選手を試合中へ変更する。
- 開始前に参加者の状態変更等で組み合わせが無効になった場合は警告を表示し、その枠だけ再計算または管理者修正対象とする。表示中の別コートのNEXT MATCHは保持する。

## 試合の状態

```text
未生成 → 次試合提示（scheduled） → 試合中（playing）
       ↘ 修正・取消                 → 結果登録 → 終了（completed）
```

- 自動計算中の候補は一時的な内部状態とし、参加者へは保存済みのNEXT MATCHのみ表示する。
- 次試合の手動修正は選手・チーム・割当コートを変更して保存する操作とする。保存後は手動修正済みを明示し、再自動生成による上書きを防止する。
- 次試合取消時は予約を解放し、未提示枠として再生成可能とする。
- 試合開始・結果登録・取消は同時更新でも一貫性を維持する。二重開始、選手の二重割当を禁止する。

## 画面とアクション

### コート状況：管理者・参加者共通

- 各コートに「現在の試合（試合中／空き）」と「NEXT MATCH（自動提示／手動修正済み／マッチング待ち）」を併記。
- スマホはコートごとのカードに現在と次試合を縦配置。PCはコートカードの一覧＋次試合の管理領域。
- 各NEXT MATCHにコート名、チームA／Bの4名、提案状態を表示。
- リアルタイム同期するが、既に提示した組み合わせは意図せず変えない。

### 管理者専用の通常フロー

1. コート状況で現在の試合・自動提示されたNEXT MATCHを確認。
2. 試合終了後、管理者が4ゲーム制の結果を登録する。
3. コートが空いたら管理者がNEXT MATCHの「試合開始」を押す。
4. 進行中の試合・次試合枠が更新され、空いた次試合枠へ自動で次候補が補充される。

### 管理者専用の例外フロー

1. コート状況のNEXT MATCHから「手動修正」へ移動。
2. 選手4名・A/Bチームの組み合わせ（必要ならコート）を編集。重複・休憩中・試合中・他コート予約済みの選手を拒否。
3. 「変更を保存」でNEXT MATCHに再提示。手動修正済みであることを表示。
4. 「修正を破棄」で元の提案を維持する。
5. 次試合の取消は確認画面を経由し、予約を解放する。

### 参加者

- 現在の試合、NEXT MATCH、マッチング待ちを閲覧できる。
- 次試合の修正・取消・開始・スコア登録ボタンは表示しない。

## 動作確認の受入条件

- 管理者が手動実行せずとも、条件が揃うとNEXT MATCHが提示される。
- 進行中コートにも次試合を表示でき、試合中は開始不可。
- 同一選手が進行中試合とNEXT MATCH、または複数NEXT MATCHへ重複登録されない。
- 他の試合終了・戦績変更で提示済みNEXT MATCHが勝手に入れ替わらない。
- 手動修正・取消後の予約・ラベル・自動補充が整合する。
- 試合開始と結果登録でコート状態、選手状態、順位表が整合する。
- 管理者と参加者で閲覧・操作権限が分離される。
